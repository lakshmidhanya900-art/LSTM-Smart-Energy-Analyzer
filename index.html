Train the LSTM

Architecture: LSTM(48) → LSTM(24) → Dropout → Dense(16) → Dense(1). Window = 24 h → next hour. Split 70/15/15 chronological, Min-Max scaler fitted on training data only.

Tip: use desktop Chrome or Edge (WebGL) and keep this tab open and visible while training.

Problem Statement
Households cannot see future electricity demand, causing peak-time overuse and avoidable cost.
Existing System
Bills and meters report only the past; linear/statistical methods struggle with non-linear daily and weekly patterns.


Proposed System
An LSTM trained in the browser on hourly data forecasts the next hour and next 24 hours; rule-based advice is derived from the forecast and is labelled as such.
Dataset
UCI Individual Household Electric Power Consumption (≈2.07M one-minute readings, Dec 2006–Nov 2010, one household in France). Global_active_power (kW) is averaged per hour (= kWh per hour). Data is historical, so forecasts are not live readings.


LSTM Methodology
Hourly aggregation → gaps ≤24 h interpolated → chronological split → Min-Max scaling → 24-hour sliding windows → LSTM training (Adam, MSE) → test MAE/RMSE vs naive baseline → recursive 24-step forecast.
Advantages & Future Scope
No server or install, private (data stays in browser), reproducible metrics. Future: multivariate inputs, direct multi-step output, Web Worker training, live smart-meter feeds.
